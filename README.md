# 拾章 · Story Atlas

放在写作软件旁边的本地资料助手。主要用于长篇小说的人物设定回忆、原文定位、阵营关系、人物支线与灵感记录；可导出资料供外部 AI 讨论。

## 0.9 更新

- 文风工作台显示五步准备进度与当前下一步。已保存场景索引会引导继续专项分析；分析失败、待保存草案、待确认档案和可用档案各有对应入口。快捷分析档案可以跳过场景索引直接使用。
- 文风引用校验会指出具体规则或样例、错误来源编号或不匹配原因。新的失败分析保留已脱敏返回，可对照本次实际发送的样本，修改来源与连续引用，或移除无依据条目。修复在本机校验，不调用 AI，也不直接确认文风；保存后先暂停，由作者恢复剩余步骤。专项核心段落及通用跨类型证据要求保持不变。
- 旧失败任务当时未保存返回内容，无法还原丢失引用。可继续未完成步骤获取新结果，或手工提供分析 JSON；已保存索引不需重跑。失败仍不自动重试，每步模型请求最多三次，人工修复不占请求次数。旧任务保留原提示词快照，新任务使用更新的内置分析提示词。
- 文风任务支持暂停与恢复。运行中暂停会等待当前请求完成并保存，当前请求仍可能计费；排队任务立即暂停。暂停状态可跨重启保留，恢复仍需相同接口、模型和有效来源。停止任务保留原有终止语义。
- 场景识别在批次间优先让出给片段写作，写作结束后自动继续剩余识别批次。完成步骤和匹配缓存不重发。任务进度改为进度条和折叠详情，展示待处理批次、复用数、接口报告的输入/输出 tokens；识别任务按已完成批次粗估剩余时间。用量不等于实际账单，未返回用量的接口会明确说明。

## 0.8 更新

- 深度文风分析分为两步：先建立全文场景索引，再预览分类样本并分析所选专项。结构位置（章首、章末）与内容标签（对话、环境、行动战斗、心理情绪、叙述过渡）分开处理，内容可多选。
- 建立索引前显示全文字符数、段落数、识别到的章节标题和预计批次。确认后才向已配置接口逐批发送全文；排除目录、声明、广告的初标由 AI 完成，可人工纠正。章首章末指每章前后两个原文段落，标题未识别时仅定位全文首尾，不等同于自动识别所有开场、悬念或收束手法。
- 分类预览显示各类候选数、章节覆盖、样本量和原文范围，核心分类段落高亮，上下文辅助理解。每类最多选择三处，优先分布在不同章节；可修改核心段落标签或排除该段。没有样本或样本较少的类型会明确标记。
- 专项规则须有对应核心段落的原文依据；通用规律须提供至少两类、不同原文位置的证据，证据不足可只保留专项。档案保留类型、来源版本、样本量；原文或分类变化后提示重新核对。分析结果先为草案，确认后才用于写作。
- 写作可选择自动建议（最多两类）、仅通用习惯或具体专项。写作与文风核对只接收通用及本次相关的规则和样例，候选稿保存实际采用的文风快照。旧版档案仍可使用。
- 索引及分析按步骤保存，失败后手动继续，不重跑已完成步骤。相同接口、模型、提示词和批次输入可复用既有分类结果；人工分类在重新识别期间被修改时阻止覆盖。快速位置抽样入口继续保留。

深度分析的首次全文识别通常比位置抽样需要更多请求；预览显示的是样本合计，同一片段可出现在多个类型中，通用归纳还会再次读取样本。自动分类和文风归纳质量需作者结合原文判断；完成索引并不等于已形成可用文风档案。

## 0.7 更新

- 文风参考支持整本 TXT / MD：每份最多 200 万字符，参考库合计最多 1200 万字符。文件导入合计仍限 8 MB，支持 UTF-8 与 GB18030；原书在本机保存，与作品章节分开。
- 分析前新增抽样预览：默认约 4 万字符，可选 2 万 / 6.5 万。短材料完整分析，长材料从前、中、后分布抽取，尽量沿换行切分；显示完整长度、实际分析量及每段原文范围，展开可查看。确认后仅发送样本。多个勾选文档会合成一份文风，不同文风请分别分析。
- 文风库支持多份命名档案与适用场景备注。每次片段改写 / 续写选择一份已确认文风，可切换“轻度参考 / 明显参考”；档案不混用，默认轻度参考，保留人物口吻、叙述视角和情节事实。分析档案保留抽样量与来源版本，材料变化会提示核对。
- AI 设置新增“测试接口”：先保存配置，测试只发送固定短句，检查文本返回与 JSON 格式，显示模型及耗时，不携带作品或参考书。仅证明接口可用，不代表长文本生成效果已验证。密钥仍仅留在服务内存，重启后重新填写。

## 启动

需要 Node.js 22 或更高版本，不需要安装 npm 依赖。

Windows 双击 `start.cmd`，保留命令行窗口。也可以在此目录运行：

```powershell
node server.mjs
```

浏览器打开 **http://127.0.0.1:4317**。端口可通过环境变量 `STORY_ATLAS_PORT` 修改；使用自定义端口时手动打开对应地址。按 Ctrl+C 停止服务。

也可以双击 `stop.cmd` 停止本机服务（包括后台启动的实例），之后双击 `start.cmd` 重新启动。

首次打开可导入自己的章节，或点击“体验示例作品”。示例《雾渡》全部为演示数据，会显示明确标识。应用一次管理一部作品；新建或恢复前会先下载当前完整备份。

`examples/06.md` 和 `examples/07.txt` 是《雾渡》的额外演示章节，可用于体验批量导入。

## 日常流程

1. 按章导入 `.md`、`.txt` 或 `.markdown` 文件。批量导入按文件名自然排序，预览标题与所属卷。同名文件视为更新原章节，保留原编号与自定标题；不同章节请使用不同文件名。
2. 手动建立人物、阵营、关系、支线与灵感。人物的正文记录需要选择章节并粘贴能匹配的原文；作者补充与未来计划单独标记。
3. 输入人物姓名、别名或设定关键词找回资料。Ctrl+K 可全文搜索，人物档案中可以展开原文出处。最近出场通过姓名和别名匹配，仅供定位参考。
4. 在“AI 资料整理”中选择章节，使用下列任一种方式整理并确认建议。
5. 导出正文 TXT、讨论资料 TXT/MD，或完整项目 JSON 备份。

## 两种 AI 整理方式

### 软件内调用

在“AI 资料整理”填写服务商的接口基础地址、模型 ID、API Key，保存接口配置。勾选“导入后自动整理”，此后新导入或更新正文的章节会逐章排队；也可以手动选择已有章节加入队列。接口须兼容 **Chat Completions**（在基础地址后追加 `/chat/completions`）。不支持仅提供 Responses API 或其他独有协议的接口。

API Key 只保留在本机服务的当前内存会话中，不写入项目文件、浏览器存储、任务记录或备份；停止服务后需要重新填写。接口地址、模型名与自动整理开关可保存。远程服务需要 HTTPS；本机模型可填写 HTTP localhost 地址并按服务要求留空密钥。请求会发送待整理章节正文、已有名称索引及涉及人物的少量前文正式设定；不发送作者计划、原始插图或整本正文。费用由所选服务商决定，每章请求超时为 120 秒。

关闭浏览器不会停止后台队列，需保持本机服务运行。暂停或清除会话只阻止后续任务，正在处理的一章会继续完成。失败不会自动重试，避免重复调用；服务停止时中断的任务也需要手动重试。原文变更后旧结果会标记失效，不能直接确认入库。

真实服务商调用需要你自己的配置；项目自带测试不调用付费接口。

### 外部 AI 导回

1. 选择章节，点击“导出整理任务 TXT”。
2. 将任务交给自己的 AI，要求按文件规定返回 JSON。
3. 粘贴返回的 JSON，或导入 JSON 文件。
4. 在确认列表检查内容及出处，可修改描述、关联章节和原文片段。勾选后确认入库；未勾选内容保留待确认。

原文匹配只验证引用片段存在，不保证提取结论正确。关系方向、人物谎言、推测语气和状态变化仍需作者审核。提取的新信息会追加，旧记录需要作者在档案中编辑或合并。暂不自动进行事实冲突裁决。

## 文风工作台

1. 在“AI 资料整理”配置接口会话。工作台共用同一个接口和模型，无需为五个角色分别配置。
2. 打开“文风工作台 → 参考与文风”，导入或粘贴有代表性的参考文字，勾选材料后分析。一次分析最多选择 12 份、合计 6.5 万字符；单份材料至少 30 字符。材料只用于分析表达，不成为目标作品的人物或情节资料。
3. 查看分析结果，保存为文风草案。逐条核对证据、调整规则与样例，再确认档案。生成时采用启用样例中的前 5 个；建议针对日常、行动、对白等场景分别建立档案。
4. 在“片段写作”选择文风与任务。章节模式先载入正文，再确认选区或章末位置；粘贴模式可指定作品资料截止章节。单次片段最多 1.2 万字符，目标篇幅约 100—3000 字，实际字数由模型决定。
5. 填写本次要求与事实边界后生成。系统准备相关已确认资料，生成初稿，并分别进行情节与文风核对；如启用修订且发现问题，再修订一次并复核。查看候选和核对意见，保存、复制或导出；采用到原始文件后可通过章节目录同步。

文风分析通常为 1 次模型请求；片段写作为 4 次，触发修订时最多 7 次。失败不自动重试；“继续未完成步骤”会跳过已成功步骤，每个步骤最多尝试 3 次。手动继续可能产生新的接口费用。任务记录显示实际调用次数、步骤、当时的规则、事实、模型和提示词版本。上述为可追溯的输入输出记录，不保证模型结果可精确复现。

每个角色仅收到本次职责需要的资料，模型无文件写入工具。章节模式按所选位置过滤已记录事实、状态与关系，避免使用后续章节或同章后续的证据；粘贴模式按截止章节过滤。它依赖已录入资料及出处，未记录的人物变化与隐含信息仍需作者核对。参考材料、片段、相邻文字和相关作品资料会发送到配置的接口，未配置时不会生成。

任务运行中可停止并保留已有候选。关闭浏览器不停止后台任务；停止服务后，未完成任务须手动继续，并重新配置接口会话。继续旧任务要求接口地址、模型与原始章节 / 材料版本一致。原文变更后仍可查看旧结果，但不能直接保存为新候选；已保存的候选也会提示基于旧版正文。

内置提示词可在“Agent 职责与提示词”调整。新任务会固定当时的提示词和文风档案版本，之后的修改适用于新任务。两个审查角色使用同一个模型，可能出现共同遗漏；“未发现问题”只代表此次模型核对结果，作者仍决定是否采用。

## 保存与备份

- 全部资料保存在 **软件目录 `data/project.json`**，通过本机服务写入文件。关闭浏览器再打开仍可读取；需要使用同一目录启动服务。
- Git 仓库仅保存软件源码、测试与演示章节。`data/`、`library/`、作者专用导入脚本、预览截图及本机密钥文件已忽略；上传或拉取源码不会备份小说，请另行保管完整项目 JSON 或 `data` 目录。
- 每次成功保存保留上一份 **`data/project.previous.json`**。这只是一份上一版本副本，不是完整历史。
- 日期快照在 **`data/snapshots/`**，“资料维护”可直接恢复。快照当前不自动删除；定期将完整 JSON 或整个 data 目录备份到其他磁盘。章节目录配置保存在 **`data/chapter-source.json`**，不随项目 JSON 或快照恢复，换电脑后需重新选择目录。
- AI 队列与尚未领取的结果单独保存在 **`data/ai-jobs.json`**，重启后可继续查看。完整项目 JSON 只包含已领取至确认列表的建议，不包含队列记录；备份前可先领取结果，或停机后备份整个 `data` 目录。
- 文风参考材料、档案、已保存候选与自定义提示词位于项目 JSON 的 `studio` 字段，随完整备份与快照保存。尚未保存到档案的工作台任务、输入与结果位于 **`data/studio-jobs.json`**；若需要完整任务历史，停机后备份整个 `data` 目录。页面显示最近 100 个任务。
- “导出与备份”中的完整项目 JSON 包含正文、正式资料、待确认建议和接口地址/模型名，可通过“恢复项目备份”恢复。精简讨论资料不能恢复全部项目。
- 建议定期将完整 JSON 另存到自己的备份目录。切换作品前也可以主动备份。
- UTF-8 为首选文本编码；遇到无效 UTF-8 会尝试 GB18030。TXT 导出使用 UTF-8 BOM，方便 Windows 编辑器读取。
- 读取到损坏的项目文件时，服务会停止并保留文件，不会用空数据覆盖。可先复制保存原文件，再将 `project.previous.json` 复制为 `project.json` 后重启。

## 当前版本边界

本地单人使用，无账号与云同步；不提供完整正文编辑器。分卷大纲将作者计划和实际进展分开保存。阵营关系图最多同时展示 30 位人物，可按阵营筛选；全部人物仍可在档案检索。人物时间线提供已记录状态的章节回看；人物简介、阵营成员列表与别名仍为当前档案，不构成全书任意时刻的完整历史快照。修改旧章节后提示复核关联资料，不会自动覆盖作者结论。

导入单批上限 50 MB，目录检查上限 1000 个文本文件、50 MB、8 层子目录；忽略隐藏目录和符号链接。完整恢复文件上限 70 MB，保存请求上限 80 MB。导出全书或全文搜索的性能取决于作品大小和电脑内存。
